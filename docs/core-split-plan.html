TaoDBM 二期 · Core 多工程拆分方案

依据：《架构升级初步方案》§7.3（已过审）· 老板 2026-11-15 拍板 · 执行位置：二期新树 /root/workspace/TaoDBM-phase2

一句话方案：把一期的单工程 src/TaoDBM 按依赖方向拆成 App / Core / Core.Abstractions / Infrastructure 四个工程加两个辅助工程，命名空间不变、源码逐文件原样搬运，只在搬运时补一期遗留的 OpenStream 缺定义；类库与逻辑测试在本机 .NET 10 已验证 零错零警。

一、目标结构

对应方案 §7.3 的目标结构，二期新树 TaoDBM-phase2/：

TaoDBM.slnx ├── src/TaoDBM.App/ # WinUI3 壳：App、MainWindow、app.manifest、Assets/、UI/ 13 文件 ├── src/TaoDBM.Core/ # 领域逻辑：Streaming/、DataSync、导入导出、报表、DDL 等 ├── src/TaoDBM.Core.Abstractions/ # 契约：IQueryConsumer、QueryPage、StreamingQuery、QueryResult ├── src/TaoDBM.Infrastructure/ # 存储、凭据、外部 IO：Providers/、Safe、SshTunnel 等 ├── tests/TaoDBM.LogicTest/ # 逻辑测试，改为工程引用 └── tools/TaoDBM.TypeCheck/ # Linux 侧类型检查（Stubs 方案）

二、文件归属映射

Core.Abstractions（4 个契约文件）

  • Core/Streaming/IQueryConsumer.cs、QueryPage.cs、StreamingQuery.cs
  • Core/QueryResult.cs —— 因 IQueryConsumer 签名引用它，留在 Core 会成环，故一并上移

Infrastructure（存储、凭据、外部 IO）

  • 根层 13 个：AppLog、AppPrefs、AtomicWrite、TaoPaths、ConnectionStore（含 ConnectionProfile）、Favorites、QueryHistory、TabSession、ThemeStore、ThemePalette、SshTunnel、Safe、DbEngine
  • Providers/ 4 个：Engines、MongoProvider、RedisProvider、RelationalProvider

Core（领域逻辑）

  • Streaming/：QueryRouter、StreamingSwitch、TaskCenter（按一期实际位置保留在 Streaming 下）
  • 平铺 11 个：DataSync、BackupTools、TableDdl、ErdModel、Faker、SeedPlan、CsvImporter、JsonImporter、ReportBuilder、SqlHighlighter、TnsNames

App（WinUI 壳）

  • App.xaml(.cs)、MainWindow.xaml(.cs)、app.manifest、Assets/（ico + png）、UI/ 13 文件（含 Exporter）
边界说明：一期原 logictest 与 typecheck 两个辅助工程因逐文件 <Compile Include> 引用，搬进新树后路径失效；本方案将其重建为独立工程目录（tests/、tools/），由工程引用替代逐文件登记。

五、一期遗留问题及处理

  1. OpenStream 缺定义：一期 HEAD（a049e4a）源码本身编译不过，QueryRouter 与 logictest 逐文件 Compile 未包含 RelationalProvider 的 OpenStream，掩盖了问题。拆分时以最小补齐修复（见上表）。
  2. logictest 逐文件 Compile：新增文件需手工登记（goal.md 已记录），拆分后由工程引用彻底消除。
  3. TaskCenter.Runner internal：一期 logictest 与主工程同 assembly，可访问 internal；拆分后用 InternalsVisibleTo 显式声明。
